# v0.1.0-alpha 快速开始与部署责任

状态：发布准备完成后仍需 #60 人工法律审核；尚未公开发布，尚未按 AGPL-3.0 获批授权。本文件描述可验证的本地源码运行方式和部署责任，不表示已有可登录的公网托管 Alpha。

## 干净环境快速开始

从本版本源码的全新目录开始：没有旧 `.env`、`node_modules`、`.next` 或历史业务数据。准备 Node.js `>=22.22.2`、pnpm `11.5.2`、Docker/Compose。浏览器安装命令在 Linux 可能请求安装系统依赖的管理员权限。

```sh
node --version
pnpm --version
docker compose version
pnpm install --frozen-lockfile
pnpm --filter web exec playwright install --with-deps chromium webkit
pnpm demo:alpha
```

**成功判据：退出码 0、4 passed**，包括 Desktop Chrome 和 Mobile Safari 各自的推荐清单与暂无推荐旅程。pnpm 安装、镜像拉取和浏览器下载需要网络，业务演示无需真实第三方账号。建议用没有配置供应商秘密和 `E2E_*` 变量的新终端。

命令复用 #58 的 `first-recommendation-journey.spec.ts --grep Alpha`，从空卷开始，按顺序拉起 PostgreSQL、Redis、MinIO、Mailpit，初始化私有资料 bucket 并迁移，再启动真实 Nest API/Worker 与 Next.js 生产构建。不是静态截图或前端假数据。测试配置使用 `APP_ENV=test`、确定性 Fake Adapter 和禁用公开来源网络的模式；测试专用场景不能用于 local/production。

端口：Web 3120、API 3121、PostgreSQL 55420、Redis 64790、MinIO 59100/59101、Mailpit 58126/31125。固定隔离项目为 `job-copilot-issue-2-e2e`，同时只能有一个演示或 E2E 进程。**每次演示启动和退出会清空该项目的测试卷**。不要把该项目当作真实数据环境。

## 两种虚构演示结局

所有人物、联系方式、公司、岗位、画像事实、薪资和结果均为合成夹具，不能用于投递、联系或营销效果证明。输入材料：[fictional-career.md](../demo/fictional-career.md)。程序通过真实上传页面导入此文件，再通过已认证公开 API 确认画像、保存主求职目标和 Watchlist；没有向数据库注入推荐结果。

| 场景 | 演示输入与操作 | 必须看到的结果 |
| --- | --- | --- |
| 推荐清单 | 合成 TypeScript 前端画像；上海、远程；虚构来源 `Alpha 58 Synthetic Fixture`；接受运行前检查警告后开始发现 | `高级前端工程师（合成验收）`，公司 `=合成验收公司`；1 项资格通过、1 项最终推荐；Inbox、归档恢复和不可变 CSV 均可验证 |
| 可信暂无推荐 | 独立合成账户，同样的来源；把主求职目标月薪改为 CNY 50,000–60,000；岗位范围为 CNY 30,000–45,000 | “今天暂无推荐”；来源覆盖大于 0、资格评估 1 项且淘汰 1 项、推荐 0 项；旅程永久完成 |

两种场景都从未准备状态开始，检查键盘、移动端、无障碍和永久完成；后续撤销画像不会重新打开首次旅程。演示来源 URL 仅用于合成来源身份，不应在真实招聘网站搜索该公司。

若希望观看自动操作：

```sh
pnpm demo:alpha --headed
```

这是自动化演示；浏览器和数据在结束后关闭/清理。要进行日常交互和保留资料，使用下面的本地运行方式，不能把演示会话当作普通账户。

## 日常本地运行与运行服务配置

完成锁定依赖安装后：

```sh
pnpm dev
```

启动地址为 [Web](http://127.0.0.1:3020)、[API readiness](http://127.0.0.1:3021/health/ready)、[OpenAPI](http://127.0.0.1:3021/openapi.json)。readiness 必须成功，页面应显示 `v0.1.0-alpha`。缺少 Docker、迁移失败或依赖不健康时，启动失败应先修复原因。readiness 是基础设施检查，不等价于模型连接已配置。

`.env.example` 记录默认端口，启动器不自动读取 `.env` 文件；在同一 shell 中导出端口与部署级配置。默认启动器固定 `APP_ENV=local`、Dev Auth、本地数据库/Redis/MinIO/Mailpit 配置，不是生产 Secret Manager 或生产启动器。数据库和对象存储示例密码只用于本机。

| 配置 | 提供者与用途 |
| --- | --- |
| `OPENAI_API_KEY` | 部署者提供给服务端的模型连接凭据；求职账户不填写 |
| `OPENAI_ENDPOINT` | 可选的 Responses API 端点，必须符合既有模型 Adapter 安全约束 |
| `OPENAI_ORGANIZATION`、`OPENAI_PROJECT` | 可选供应商组织/项目，仅部署环境持有 |
| `OPENAI_LOW_COST_MODEL`、`OPENAI_HIGH_QUALITY_MODEL` | 按 ADR 0019 与当前 Adapter 配置选择；改变后重新进行合成连接诊断 |
| `PUBLIC_JOB_DISCOVERY_ADAPTER=greenhouse` | local 模式显式使用已支持的真实 Greenhouse 来源；默认使用 Fake 发现，不自动代表真实来源质量 |
| `ANYSEARCH_API_KEY` | 生产分层公开发现的可选部署级凭据；仅设置此项不会把 local 模式切换为生产分层发现 |

不配置真实凭据也能启动 Web 和依赖，但 local 下模型诊断可能阻塞运行，不能据此承诺完整推荐；无需凭据的完整旅程请用 `demo:alpha`。不要为绕过阻塞把测试开关设置到托管环境。生产形态依据 ADR 0033 使用分层来源，AnySearch 仅提供未经验证线索，真实岗位仍需本地安全抓取与验证。

运行时的模型诊断使用固定合成输入，账户只收到脱敏可用状态、稳定失败原因和有限下一步；密钥、供应商账户信息和原始响应不进入求职画像、下载或普通日志。文档不要求通过命令行回显密钥；应使用部署环境的秘密注入设施。

退出：先在运行终端 `Ctrl-C` 停应用，再执行 `pnpm dev:down` 停依赖。数据卷默认保留。多份本地副本应设置不同 `COMPOSE_PROJECT_NAME` 和全部端口，使用相同配置关闭对应项目；不要与已有用户环境共用数据卷。

## 邀请制托管与自行部署的责任

托管服务具备上线条件后，受邀求职者由运营方获得访问入口与邀请，完成认证后在首页按旅程上传职业资料、确认画像、设置目标和来源，再检查并启动今日发现；无需安装 pnpm/Docker 或申请服务密钥。自行部署者先完成上面的运行环境准备，再以求职账户进入同一旅程。当前没有随本包交付的公网托管地址。

| 项目 | 邀请制托管环境 | 自行部署环境 |
| --- | --- | --- |
| 求职账户 | 上传获授权职业资料、确认事实/目标、选择来源、收紧运行额度、决定运行和全局停止 | 相同产品权利和安全契约 |
| 运行服务凭据 | 运营方持有、注入、轮换、承担供应商成本 | 部署者自行申请、注入、轮换并承担成本 |
| 数据服务 | 运营方维护数据库、队列、对象存储、备份恢复与访问控制 | 部署者承担相同运维责任 |
| 账户额度 | 运营方配置系统硬上限，用户只能收紧；展示脱敏有效额度和服务状态 | 部署者配置系统硬上限，用户只能收紧；不提供求职账户密钥管理 |
| 邀请与认证 | 运营方在服务开放前完成真实身份认证、邀请访问控制、TLS 与资料保护 | 部署者同样不能把本地 Dev Auth 和示例密码直接对公网开放 |
| 对外发布 | 维护者完成 #60 法律决定及批准条件后才能推进 | 取得源码不等同于本仓库已授予未经批准的许可证 |

托管与自行部署共享领域、Adapter、数据库和安全契约。Alpha 没有支付、订阅、购买额度或计费页面，求职账户不上传、查看、下载或轮换运行服务秘密。展示的运行预算不是付费余额。

本包未交付生产托管编排和真实微信 OAuth；尚需独立认证/访问保障与上线验收。当前只可在本机或严格隔离的开发环境验证，不能称已具备公网邀请制托管服务。

## 排错与升级

- 安装失败：记录包仓库/镜像/浏览器下载错误，修复网络或工具版本后重试；不要关闭锁文件和供应链校验来凑通过。
- 端口占用：停止占用测试端口的既有演示/E2E；不得并发测试或擅自停止不属于自己的服务。
- 启动失败：检查 Docker、Compose readiness、MinIO 初始化和迁移输出；此时不计作业务验收通过。
- 断言失败：保留 `apps/web/test-results` 的错误上下文和 trace，按产品缺陷、测试缺陷或环境失败分类；不要增加重试或改成跳过。
- 异常退出后先确认本次应用进程已停止，再按需执行 `docker compose --project-name job-copilot-issue-2-e2e down -v --remove-orphans`。只允许清理该专用测试项目。

trace 可能含合成会话令牌，留在本地，不直接上传 GitHub。升级/备份/回退要求见[变更记录](../../CHANGELOG.md)。完整测试范围与本次结果见[验收记录](../acceptance/alpha-release-package.md)。
