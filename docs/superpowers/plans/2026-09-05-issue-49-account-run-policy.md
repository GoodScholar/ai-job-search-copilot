# Issue #49：账户运行策略与系统硬上限

已批准方案：账户策略以当前指针和不可变修订保存；读取同时返回系统默认值、硬上限、用户设置与最终生效值。所有写入按认证账户、`expectedVersion` 与账户事务锁处理。手动运行与每日检查计划共用有效策略；新运行绑定策略修订和预算快照，检查点继续服从系统硬上限。

默认值与硬上限：每次发现可信来源 50/50；公开搜索查询 5/10；待验证候选 10/10。PUBLIC：180000ms/3 attempts/60 tools/5 results/0 model/0 tokens；DEEP MATCH：180000ms/3/0 tools/10 results/10 model/20000 tokens；fake 保持旧预算兼容。后台窗口为 Asia/Shanghai，默认 08:00–22:00，用户可跨日，`start === end` 无效。

TDD 切片与进度：

1. 契约及领域持久化：已完成真实 revision 0 基线、不可变修订、账户锁、结构化硬上限原因、跨账户隔离、真实并发竞争，以及运行策略引用的成对约束和所有者复合外键测试。
2. 运行与计划接缝：已完成。新发现、手动及自动深度匹配均冻结修订、来源范围和预算；结果、详情、候选发布及持久化均按快照与当前硬上限的逐维最小值收口。计划窗口校验 `dailyTime`，派发与启动事务均校验实际时刻及 occurrence 时刻；历史运行保持双空策略引用。
3. API/BFF：已完成认证 GET/PUT/history、结构化硬上限/空窗口/409 错误映射，以及真实 API client 到 BFF 的错误体回归。
