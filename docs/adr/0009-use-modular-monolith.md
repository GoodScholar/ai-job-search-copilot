# 使用模块化单体与独立 Worker

首版采用模块化单体，求职画像、岗位、匹配、材料和投递形成内部深模块，共享一个 PostgreSQL；后台 Worker 作为独立进程部署并通过持久任务执行 Agent 运行。系统不在缺少独立扩缩容、团队所有权或故障隔离证据时拆分微服务，岗位来源和模型供应商只在存在生产与测试 Adapter 的真实 seam 上建立端口。

## Considered Options

- 微服务：隔离明确，但会提前引入分布式一致性、部署和可观测性成本。
- 无模块单体：部署简单，但领域逻辑容易跨调用方扩散。
- 模块化单体与独立 Worker：保留低运维成本，同时让长任务与请求处理分别扩展。
